## Migration policy

`0002_review_history.py` adds columns/tables and backfills the previously retained extraction only. Existing account, case, document, correction, storage-name, and monetary values are preserved. The backfilled run's timestamp is null, its parser version is unknown, and older correction bases remain unknown. Legacy reviewed documents receive a source-history limitation; the UI permits an explicit audited review. Unknown legacy embeddings are retained but never compared as if they came from the active model.

There is no destructive downgrade. Explicit backups were taken before validation; no application table reset or volume deletion is part of startup. Read `VALIDATION.md` for current measured outcomes, separate from historical author-machine checks.

Additional regressions verify that a save acknowledgement includes assigned row IDs before a second edit, and that unknown unit placeholders cannot confirm quantity/price differences.

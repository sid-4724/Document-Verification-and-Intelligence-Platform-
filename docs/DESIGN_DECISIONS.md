# Implemented design decisions

| Decision | Alternative | Actual trade-off |
| --- | --- | --- |
| Deterministic verification in `verification.py` | Ask a model to compare amounts | Code can test exact arithmetic and explicit prerequisites. It supports a bounded set of business rules, not arbitrary commercial interpretation. |
| Decimal values constructed from strings | Binary floats for money | Decimal avoids binary representation error. Rounding policy is still an explicit case tolerance; the code does not infer a jurisdiction or tax rule. |
| Null means unknown; zero means measured zero | Fill missing numbers with zero | Missing values produce review and skip unsupported comparisons. This reduces false mismatches, at the cost of needing human review. |
| Stable row IDs stored inside extraction JSON | Hash row descriptions/values or create a line-item service/table | Identical repeated rows remain distinct. JSON fits the existing modest schema. Editing values keeps identity; deleting/re-adding creates a new row. |
| Finding hash includes rule/pair/row identity and material facts | Hash visible text alone or randomize IDs on refresh | Reordering persisted rows preserves IDs and review status. Material changes reopen findings. Unique unchanged source anchors keep raw row identity across reprocessing; ambiguous remapping does not guess. |
| Identifier → exact description → fuzzy candidate | Mix every resemblance into one candidate set | Different nonempty identifiers require review. Strong exact evidence wins over weaker fuzzy evidence. Fuzzy-only matches stay reviewable and do not confirm quantity/price differences. |
| One reference, individually selected targets | Every possible pair or automatic invoice aggregation | Targets are never compared with one another. Several invoices produce an explicit partial-fulfilment/unsupported-aggregation warning. Individual deltas are not an aggregate fulfilment conclusion. |
| First retained extraction plus processing history | Overwrite `original` on reprocess | New raw data is available without losing retained history. Corrections stay on their own run basis; a new extraction does not silently merge incompatible rows. Storage grows with runs. |
| Additive `0002` migration with honest legacy metadata | Reset databases or invent historical runs | Existing records and values remain. Only the previously retained snapshot can be backfilled; its processing time and old correction bases can be unknown. Legacy reviewed data is flagged until explicitly reviewed. |
| Separate source limitations from field validation | Rebuild all warnings after every save | Filling a missing quantity can remove its warning. Editing a field cannot establish that an unreadable page was read. Explicit source review records its reason and reviewer. |
| Expected document revision and conditional write | Last submitted form wins | Stale tabs get 409 and retain their draft. Users must reload and review against current values. PostgreSQL case locks serialize writers; the conditional document write also protects SQLite. |
| One database worker with leases/retries | Redis/Celery/microservices | Durable jobs use infrastructure already required by the app. There is no heartbeat or multiple-worker throughput claim; tokens prevent late results from overwriting newer work. Failed/expired attempts are recorded. |
| Separate original passages and reviewed records | Feed only findings or describe corrections as source text | The provider receives a complete effective snapshot with audit/run provenance for reviewed scope. Original scope receives no corrected records. Valid citation IDs establish membership, not sentence-level entailment. |
| Model/configuration metadata stored with vectors | Compare every stored array of the right length | Different weights/configurations and unlabelled legacy embeddings fall back to keywords. Remote resolved commits or a local file hash identify weights; dimension alone is insufficient. |
| Runtime chunk evaluation with case-separated validation/test | Report whole-document metrics as runtime quality | Thresholds use validation only. Gold fragments identify actual page/chunk relevance. Old whole-PDF numbers remain a separate baseline. Both datasets are small and synthetic. |
| Guard/cancel loads and protect dirty drafts | Let the latest arriving response set the editor | Rapid selection cannot display/save the wrong document. Keeping the form draft requires explicit discard/reload behavior rather than silent refreshing. |
| Focused route groups and services | One large route module or many generic layers | The call path remains short: route → focused service → pure rule. `main.py` handles composition/security; the UI hook handles loading, and panels handle coherent views. |
| Dedicated test target plus explicit external opt-in | Trust an arbitrary TEST_DATABASE_URL | Fixture DDL refuses the application identity and its database name even through host aliases. Default tests use temporary SQLite. Opt-in still requires careful operational use of a genuinely disposable database. |
| Pinned validated container digests and existing dependency locks | Move to whatever mutable image tags resolve today | Builds avoid an unintended base upgrade and used cached validated images after a registry DNS failure. Updating dependencies remains a deliberate future change. |

This is an AI-assisted portfolio implementation. Decisions should be explained from the code and evidence, without claiming a manual authorship history or production readiness.
